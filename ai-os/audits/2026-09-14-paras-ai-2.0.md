# Paras AI 2.0: audit and honest assessment

Date: 2026-09-14. Examined the current workspace, all 53 role files, all 73 workspace skill entrypoints and available supporting files, 12 commands, current plans, memory paths, dashboard request paths, operating logic and selected live read-only connections. This is a structural audit with targeted runtime checks. It doesn't certify every specialist's output, third-party plugin or separate trading/media application.

## My assessment

The useful idea is a personal operating foundation connecting learning, distribution, community and reliable delivery. It fits a founder and small service-business team. Enterprise is not a prerequisite. Its value should be demonstrated through completed customer work, time recovered and reliable decisions.

The main weakness is an imbalance: there are many specialist prompts and plans, while evidence that complete business processes work is thinner. A role library can help with drafting and analysis. It cannot prove that a member received a resource, payment granted the right access, or a failed job alerted an owner. Calling the whole system autonomous now would overstate the evidence.

Keep the three pillars as navigation, with memory and technical operations underneath. Keep Invest OS separate from the current commercial engine. A larger agent roster or a replacement stack is not the next priority.

## What still needs work

**Context ownership.** Several historical files called themselves the source of truth. The new starting point helps; weekly review must keep decisions, assumptions and evidence distinct.

**A complete customer path.** The local plan still records eleven business blockers. Resource delivery, consent, checkout, entitlement, onboarding and renewal/failure handling need actual end-to-end tests. This matters more than adding another visual interface.

**Durable execution.** Current model calls produce drafts. The voice approval store is in process memory and expires; a restart discards pending actions. Before unattended customer operations, add a durable action journal with approved scope, status, attempts, destination receipt, failure reason and deduplication key.

**A smaller everyday interface.** Keep the library, but present a short task menu: prepare content, review onboarding, handle support exceptions, review metrics and update memory. Measure use before retiring overlapping capabilities.

**Human ownership.** No automation maintainer is named and team throughput remains unconfirmed. Each routine needs an owner, response expectation and manual fallback. AI doesn't remove this requirement.

**Actual portability.** Paths and source layout are cleaner, but credentials, workflow state, payment mappings and private notes aren't contained in Git. A fresh-machine restore exercise remains necessary. See [PORTABILITY.md](../../docs/PORTABILITY.md).

**Security beyond one operator.** Basic authentication and command filters are limited. The hook doesn't cover every shell, API or MCP tool. Client or multi-user deployment needs separate identities, least-privilege permissions, durable authorization, tenant separation, audit logs and recovery tests. This cleanup doesn't claim those controls exist.

## Research and its application

Use fixed workflows for repeatable work and agent reasoning where judgment is needed. Anthropic recommends simple designs and adding complexity when task performance warrants it. My application here is one coordinating conversation using existing specialists, with n8n/code handling stable steps. [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents).

Evaluate final state: a delivered file, correct CRM record or verified entitlement. A convincing completion message is weaker evidence. Create a task bank from actual work and synthetic edge cases; grade accuracy, completion, approval compliance, cost and time. Anthropic distinguishes outcomes from transcripts and combines deterministic, model and human evaluation. [Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents).

Treat relocation as recovery. n8n credentials depend on encryption configuration and database state; source files alone can't recreate them. Preserve compatible backups and test restoration against the installed version. [n8n encryption and backup requirements](https://docs.n8n.io/deploy/host-n8n/configure-n8n/security/rotate-encryption-keys). Keep Obsidian recovery copies independent of sync. [Obsidian backup guidance](https://obsidian.md/help/backup).

Keep capital execution isolated. Automated trading can create losses without consulting the owner on each trade. The SEC alert describes that general risk; it doesn't establish the legal regime for Paras's future project. My recommendation is separately owned research, tested simulation and defined execution controls before a funded experiment. [SEC auto-trading investor alert](https://www.sec.gov/about/reports-publications/investorpubsautotradinghtm).

## Recommended sequence

| Priority | Work | Acceptance evidence |
|---|---|---|
| 1 | One resource-to-member workflow | Resource delivered, consent recorded, sandbox payment matched to access, onboarding received, errors visible |
| 2 | Action journal and exception queue | Every action has owner, approved scope, input, state and receipt; retries don't duplicate outcomes |
| 3 | Named operator and simple daily view | Due work, blockers and approvals visible; agreed owner and fallback per routine |
| 4 | Representative task evaluations | Proposed initial 20 cases across content, support, metrics and failures; repeated measured results |
| 5 | Restore the working slice elsewhere | Fresh environment reproduces it from source, configuration and encrypted backup; recovery time recorded |
| 6 | Expand one industry use case | Separate account/data context; verified customer outcomes and manageable support load |

Twenty cases is a proposed starting scope, not a benchmark. Include missing resources, duplicate webhooks, revoked consent, failed renewal, stale prices, unsupported claims, an unavailable model and restart during work.

The next milestone I recommend is two weeks of reliable use on the same small set of business tasks, with receipts and an exception owner. That is a proposed validation window, not current performance. Increase autonomy after that evidence exists.
